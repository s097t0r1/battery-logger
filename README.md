Исследовательский логгер батареи для Android: проверяет, как часто и насколько точно
фоновая работа выполняется на реальных телефонах разных производителей, в режиме Doze и
с настройками энергосбережения OEM по умолчанию.

Приложение раз в заданный интервал записывает состояние батареи и системы в CSV-файлы
на самом телефоне. Потом файлы забирают через USB (`adb`) или кнопкой «Поделиться».

---

## 🔒 Приватность

**Приложение не может выходить в интернет и ничего никуда не отправляет само.**

- В манифесте **нет** разрешений `android.permission.INTERNET` и
  `android.permission.ACCESS_NETWORK_STATE`. Без `INTERNET` Android не даёт приложению
  открыть ни одного сетевого соединения. Это ограничение системы, а не обещание в коде.
- Это проверяется автоматически: при каждой сборке CI извлекает итоговый манифест
  из APK и **роняет сборку**, если в нём появилось сетевое разрешение (в том числе
  подтянутое случайно, например через библиотеку).
- У приложения **нет зависимостей**, только стандартный API Android. Нет аналитики,
  рекламы, трекеров и crash-репортёров.
- Все данные лежат только на телефоне в папке приложения (см. [Файлы](#-файлы)).
- Отправка логов возможна только вручную: по нажатию «Поделиться» вы сами выбираете,
  куда отправить файлы (почта, мессенджер и т. п.). Вместе с файлами уходит короткий
  текст: модель телефона, версия Android и сборки, имя сессии.
- Доступ к файлам через «Поделиться» выдаётся только выбранному приложению и только на
  чтение. Провайдер файлов закрыт для всех остальных.
- Резервное копирование данных приложения отключено (`allowBackup="false"`).

## 📲 Установка

1. Скачайте APK со страницы [Releases](https://github.com/OWNER/REPO/releases/latest).
2. Установите (разрешите установку из неизвестных источников) или через `adb`:
   ```bash
   adb install battery-logger-v1.0-debug.apk
   ```
3. Откройте приложение и разрешите уведомления.
4. Для режима B включите «точные будильники» кнопкой в приложении.

> ℹ️ Релизы — это debug-сборки: их достаточно для эксперимента, а режим debuggable даёт
> запасной путь к файлам через `run-as`. Каждый релиз подписан своим ключом, поэтому
> **новую версию нельзя установить поверх старой**: сначала заберите логи, потом удалите
> приложение и поставьте новое.

## 🧪 Протокол прогона

1. Установить, открыть, выдать уведомления. Для режима B включить точные будильники.
2. Сохранить свойства системы (версия One UI / HyperOS и пр.):
   ```bash
   adb shell getprop > props_<device>.txt
   ```
3. Записать в протокол настройки энергосбережения производителя («спящие приложения»
   Samsung, ограничения Xiaomi и т. п.). **Оставить по умолчанию, ничего не менять.**
4. Нажать «Старт» → **отключить USB** (зарядка и adb мешают Doze) → выключить экран →
   не трогать N часов.
5. Подключить телефон, нажать «Стоп», забрать файлы.
6. Режимы A и B запускать **отдельными прогонами**, иначе будильники B будят и A.
7. Калибровка знака тока: короткий прогон на зарядке и без неё.

### Как забрать файлы

```bash
adb pull /sdcard/Android/data/com.example.batterylogger/files/ ./<device>/
```

Если на каком-то телефоне `adb` не видит `Android/data`:

```bash
adb shell run-as com.example.batterylogger ...
```

В этом случае путь будет внутренним; он записан в `storage_path` в паспорте сессии.

Можно и без компьютера: кнопка «Поделиться» отправит файлы последней сессии.

## 📁 Файлы

```
Android/data/com.example.batterylogger/files/
├── process_exits.csv            # причины гибели процесса (ApplicationExitInfo), общий для всех сессий
└── sessions/<yyyyMMdd_HHmmss_mech>/
    ├── passport.csv             # паспорт устройства и сессии: key,value
    ├── samples.csv              # одна строка на тик
    └── events.csv               # старт / стоп / смена способа планирования
```

## 🛡️ Что гарантирует код

Всё это можно проверить по манифесту:

- Foreground service типа `connectedDevice`, обязательное для этого типа разрешение —
  `CHANGE_WIFI_STATE` (сам Wi-Fi логгер не трогает).
- Разрешения `WAKE_LOCK` **нет**: приложение физически не может удерживать телефон
  в бодрствующем состоянии. В режиме B wake lock держит система, и только на время
  обработки будильника.
- Нет запросов на отключение оптимизации батареи и обходов OEM-ограничений.
- `START_NOT_STICKY`: если система убьёт процесс, это не маскируется автоматическим
  перезапуском.
- Одна строка лога записывается одним вызовом `write(2)` без буфера в приложении;
  `fsync` выключен (`CsvAppender.FSYNC_EACH_LINE`).

## 📊 Подсказки для анализа

| Что ищем | Как считать |
|---|---|
| Пропуски | разрывы в `slot_index` |
| Опоздание | `lateness_ms = actual_elapsed − planned_elapsed` |
| Время глубокого сна между строками | `Δactual_elapsed − Δactual_uptime` |
| Перезапуск процесса | смена `pid` / `proc_start_elapsed_ms`; причина — в `process_exits.csv` по времени |
| Режим B после гибели процесса | строки с `fgs_alive=false` (будильник разбудил новый процесс без FGS) |
| Средний ток | по `Δbm_charge_counter_uAh / Δt`, а не по `bm_current_now_uA` (он меряется в момент пробуждения и смещён вверх) |

Специальные значения в данных:

- `-2147483648` (`Integer.MIN_VALUE`) / `Long.MIN_VALUE` — свойство не поддерживается устройством;
- `NA` — API нет на этой версии Android;
- `absent` — в системном интенте нет такого поля.

## 🛠️ Сборка

Требуется **JDK 17**. Gradle wrapper уже в репозитории.

```bash
./gradlew assembleDebug        # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # unit-тесты
```

Или откройте папку проекта в Android Studio.

| | Версия |
|---|---|
| minSdk / targetSdk / compileSdk | 29 / 35 / 35 |
| Android Gradle Plugin | 8.7.3 |
| Kotlin | 2.0.21 |
| Gradle | 9.0.0 |

`targetSdk` одинаковый для всех устройств эксперимента: от него зависят правила
foreground service, точных будильников и значения-заглушки `BatteryManager`.

### CI

- **Build** (`.github/workflows/build.yml`) — при каждом push и pull request в `main`:
  сборка, тесты, проверка разрешений.
- **Release** (`.github/workflows/release.yml`) — при push тега `v*`: сборка с нуля,
  проверка разрешений, аттестация и публикация в Releases.

Выпустить релиз:

```bash
git tag v1.0
git push origin v1.0
```
